VSCode Codex 插件吞掉消息的临时解决方案

发表于2026-10-02|更新于2026-10-03|技术分享
|总字数:2.1k|阅读时长:10分钟|浏览量:

前言

50个小时后，OpenAI终于发布了修复版插件，版本号为26.930.31730。

完结撒花。

OpenAI DevDay之后就接连好消息不断。先是自家服务直接炸了半天，然后又是GPT-6.1-Sol奇慢无比，最后又是第二天更新给自己的Codex插件更新炸了。O\也不像人了我看。

每次VSCode内在之前的对话中继续发消息，就会吞掉第一次发的，必须重新发一遍才正常。

AI分析

VSCode内有一行日志：Failed to release queued message send lock "undefined" is not valid JSON

让AI看了下插件代码分析了下：

Codex 扩展会使用发送锁来协调消息发送。释放锁的函数执行完毕后，没有返回任何值，因此函数结果是 JavaScript 中的 undefined。随后，扩展内部的桥接层尝试通过 JSON.stringify 序列化这个结果，前端再通过 JSON.parse 解析它。

检查代码后发现，扩展释放发送锁的函数没有返回值，而负责传递结果的桥接层和前端却执行了：

也就是，发送锁实际上已经释放，但释放操作的成功响应无法被前端正常解析。日志里的“释放发送锁失败”，并不直接代表锁仍然处于占用状态。

临时修复

在释放锁的处理函数末尾补上一个明确的成功返回值：return { success: true };
